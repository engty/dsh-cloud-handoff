# 云接力（dsh-cloud-handoff）功能边界与限制说明

> 本文档面向**准备使用云接力插件的用户**，说明它能做什么、不能做什么、硬限制、已知失败模式，以及怎么用它最稳。
|> 适用版本：`0.4.1`
> 本文档由**云端研究报告**（job `f1398386`，写于 v0.3.6）作为底稿，由**本地会话结合当前代码库复核、更新**后落盘；差异见文末「落盘说明」。

## 零、云端研究模式边界（v0.4.0 起，最重要的边界）

> **云端只做研究 / 验证 / 方案；本地负责实现与落盘。云端绝不直接修改本项目的代码。**

- 云端产出**只能**写在 `cloud-research/` 目录内（`cloudResearchDir` 可配）：
  - `<主题>-复盘.md`：主交付物，固定结构 = 背景目标 → 关键结论 → 方案与权衡 → 范例代码 → 验证过程与结果 → 风险 → **给本地 agent 的实施建议**
  - `examples/`：它认为该怎么改的**范例代码片段**（仅供参考，不是可直接应用的补丁）
  - `evidence/`：验证实验的脚本与输出
- 云端**禁止**：修改 `cloud-research/` 以外的任何文件、git 操作、安装全局依赖。
- 为什么：云端只有工作区**快照**，看不到完整代码库及其关联，直接改代码必然与本地冲突。
- **回传越界过滤**：云端若碰了研究目录外的文件，插件**一律拦截、不回传**，本地卡片红字列出清单（`receipt.outOfScope` / `deletedOut`）。
- 本地取回流程：**「查看报告」（系统默认应用打开 Markdown，先看内容）→ 「交给当前会话落盘」→ 本地 agent 读报告 + 结合完整代码库制定计划 → 实现并落盘**。界面已移除「机械应用」按钮，避免未审阅就机械覆盖。

## 一、能做什么 / 不能做什么

### 1.1 能做什么（✅）

| # | 能力 | 具体行为 | 依据 |
|---|---|---|---|
| 1 | **手动一键迁移** | 在会话输入区点云朵图标 → 填一句任务说明 → 点「发送」，插件先让本地当前轮停稳，再在后台打包并上传，云端接单后继续执行 | `lib/index.js` `doSend`/`runSend`（`cancel` 当前轮 → `waitForSettle` → 后台打包上传） |
| 2 | **迁移的是"简报 + 工作区 + 记忆"，不是整段对话** | 本地先把与任务相关的上下文提炼成一份小体积简报，连同工作区快照、`MEMORY.md`/`USER.md` 一起打包；云端据此新建干净会话执行 | `lib/brief.mjs`（生成简报）、`lib/handoff.mjs` `packBundle`（`manifest.sessionLogs = []`，不再传整段会话日志） |
| 3 | **云端用 API Key 通道独立执行** | 云端会话固定走 `deepseek-official / deepseek-v4-pro`，不依赖本机登录态；任务完成后调 `dsh_cloud_finish` 把结果打包回传 | `lib/index.js` `startCloudTask`（`selectModel` 固定 provider/model）与云端工具 `dsh_cloud_finish` |
| 4 | **本地重开自动同步结果** | 本地 DSH 重启后，启动钩子与每 20 秒轮询会自动检测云端是否结束，一结束就自动下载回传包（**只下载、不落盘**，等审阅） | `lib/index.js` 启动钩子（`autoPull`）+ `setInterval(…, 20_000)` 轮询 |
| 5 | **报告可先看，再决定是否落盘** | 云朵亮绿点后卡片出现「查看报告」：把 `cloud-research/` 下的复盘报告复制到 `~/.dsh/dsh-cloud-handoff/work/reports/<jobId>/` 并用系统默认应用打开；看完再点「交给当前会话落盘」 | `lib/index.js` `open-report` 路由 + `lib/client.js` 卡片按钮 |
| 6 | **本地 agent 负责实现，范例代码仅供参考** | 取回时当前会话派子智能体：先用 `dsh_cloud_apply_result mode=report` 读复盘报告，再结合本地完整代码库制定实施计划、实现并落盘；云端范例代码不保证正确 | `lib/index.js` `injectRetrieve` / `dsh_cloud_apply_result(mode="report")` |

### 1.2 不能做什么（❌）

| # | 不能做 | 原因 / 边界 | 依据 |
|---|---|---|---|
| 1 | **不能自动检测"关盖 / 断电 / 崩溃"并自动触发迁移** | 迁移是**手动**动作（点按钮）。突发事件判断属于"突发交接"，按设计明确不做 | `README.md`「能做什么/不做什么」；`lib/index.js` 只有手动 `send` 路径 |
| 2 | **不能推送 GitHub 或任何远程仓库** | 插件只用 git 的**本地清单能力**（`git ls-files`）决定打包哪些文件，从不读取 remote、从不 push；云端改动只在本地审阅后由你手动合并到 GitHub | `lib/handoff.mjs` `scanWorkspace`（注释："永不触碰任何远程仓库"）；`README.md` |
| 3 | **不能未审阅就静默覆盖本地工作区** | 下载后的回传包处于"待取回"状态，必须经过审阅 → 派子智能体落盘；本地已改动文件一律不覆盖 | `lib/index.js` `downloadResult`（→ `RETURNED`）/ `injectRetrieve` |
| 4 | **不能把云端会话事件直接拼进本地当前会话** | 会把会话 seq 撞号、污染上下文；云端会话永不并入本地会话，只由子智能体读有界摘要（单文件 ≤200KB、会话流默认 60 行） | `README.md`「清理策略」；`lib/index.js` `readBundleFile`（`cap=200*1024`）与 `readBundleTranscript`（默认 60 行） |
| 5 | **不能同时跑多个云端任务（单任务串行）** | 发起迁移前会检查是否存在 `FROZEN`/`REMOTE_RUNNING` 的活跃任务，有则拒绝二次迁移 | `lib/index.js` `doSend`（"已有任务在云端执行"） |
| 6 | **不能在云端开放公网端口 / 暴露 RPC** | 云端 DSH 只绑 `127.0.0.1`，所有调用经你自己的 SSH 通道转发，不对外监听 | `lib/remote.mjs`（`curl http://127.0.0.1:<port>/…`）；`README.md` |
| 7 | **不能在云端使用本机登录态 / 账号型模型通道** | 云端是无头机器，模型固定走 API Key（`deepseek-official`）；账号型（登录态）模型通道在云端不可用 | `lib/index.js` `DEFAULTS.cloudProvider`/`cloudModel` + `startCloudTask` 固定 selectModel |

## 二、硬限制清单（每条给出依据）

### 2.1 模型上下文窗口

- **数值**：`1,048,576 tokens`（约 1M tokens），是真正的硬上限——与请求体字节数无关。
- **实测依据**（`lib/brief.mjs` 顶部注释，2026-10-08 @ api.deepseek.com/anthropic）：
  - 请求体 2MB → `200 OK`（4.3s）
  - 请求体 8MB → `200 OK`（83s）
  - 请求体 16MB → `400`（报 `1,398,191 tokens`，超出 1,048,576 上限）
- **影响**：把整段会话日志直接发给云端会撞上此窗口（日志动辄十几 MB）。因此迁移载荷改为**简报**，不为别的，正是为绕开这个窗口。

### 2.2 迁移简报预算

- **数值**：简报预算默认 `300KB`（配置项 `briefBudgetBytes`，可改）。
- **实测依据**（简报五「可用实测数据」）：18.3MB 日志 / 5895 事件 → 生成简报仅 35.1KB，远低于 300KB 预算；300KB ≈ 5~7 万 tokens，约占 1M 窗口的 5~7%，为云端执行过程留足余量。
- **注意**：云端下发指令时会把简报**内嵌进提示词再按 200,000 字符截断**（`lib/index.js` `startCloudTask` 中 `brief.slice(0, 200_000)`）。因此即便把预算放宽到 300KB，云端 agent 首屏实际拿到的简报也不超过约 20 万字符；更长的细节需靠云端自行读工作区文件补足。**不要把 300KB 预算误当成"可塞进 300KB 都能被模型完整读到"。**

### 2.3 工作区文件数与体积

- **数值**：单个工作区快照上限 `512 MiB` / `100,000 个文件`（`lib/handoff.mjs` `LIMITS.maxSnapshotBytes` / `maxEntries`）。
- **依据**：代码常量（对齐 Blaxel 边界）。
- **影响**：超限时**预检阶段**友好报错并**不打断当前轮**（`doSend` 先 `scanWorkspace`，失败直接返回提示，不做 `cancel`）。大文件/缓存应移出工作区或加入排除表。
- **打包排除**：`.git`、`.env*`、`*.pem`、`*.key`、`id_rsa*`、`.credentials.yaml`、`node_modules`、构建产物等自动跳过（`lib/handoff.mjs` `FILE_DENY` / `WALK_SKIP_DIRS`），并做疑似密钥内容扫描（`SECRET_PATTERNS`）。

### 2.4 子会话历史（旧导入路径的边界）

- **数值**：子会话最多导入 `32` 个、合计 `16 MiB`（`lib/handoff.mjs` `maxChildSessions` / `maxChildBytes`）。
- **依据**：代码常量。当前 v0.3.x 走的是**简报式迁移**，已不再发送整段会话日志；此上限仅对旧版"导入会话历史"路径仍有意义，列在此处防止误解历史版本行为。

### 2.5 并发

- **数值**：**单任务串行**——同一时刻只允许一个活跃云端任务。
- **依据**：`lib/index.js` `doSend` 对 `active.state ∈ {FROZEN, REMOTE_RUNNING}` 的拒绝逻辑。
- **本地历史留存**：`jobs.json` 只保留最近 `20` 条任务记录（`lib/jobs.mjs` `JobStore.patch`），操作日志 `operations.json` 只保留最近 `200` 条（`OpLog.add`）。

### 2.6 网络与代理

- **通道**：全部走 **SSH**（默认 22 端口，`BatchMode=yes` 免密、`ConnectTimeout=15s`、`StrictHostKeyChecking=accept-new`）；上传/下载用 tar-over-ssh，**不依赖 rsync/zstd**（`lib/remote.mjs`）。
- **云端监听**：只绑 `127.0.0.1`，RPC 经 `ssh exec curl http://127.0.0.1:<端口>/…` 调用，带 token 鉴权（`lib/remote.mjs` `cloudRpc`；`lib/index.js` `receive` 校验 token）。
- **出站模型请求**：云端默认**直连 DeepSeek API**；若要使用需要出站代理的模型，需**自备**代理并在 systemd 服务里设 `http_proxy`/`https_proxy` 环境变量（`docs/cloud-host-setup.md` 第 6 节）。一键脚本**不会**替你装代理。
- **超时**：单条 SSH 命令默认 120s、传输类 600s（`lib/remote.mjs` 各 `timeoutMs` 默认值）。

### 2.7 云端无登录态

- **事实**：云端是无头 DSH，**没有本地用户的登录态与账号型模型通道**；模型固定走 API Key 通道 `deepseek-official`，模型 `deepseek-v4-pro`（`lib/index.js` `DEFAULTS`）。
- **后果**：依赖"登录态才能用的模型/能力"在云端不可用；迁移时本地会把会话里的模型选择改写为 API Key 通道（`rewriteSessionCwd` 的 `modelProvider` 改写）。
- **记忆文件注意点（已知限制，待改造）**：`MEMORY.md`/`USER.md` 由本地复制到**云端共享的 mnemon 目录**（非按 jobId 隔离）；不同工作区发到同一台云端时，这些记忆文件会互相覆盖。
  - 计划（v0.4.x）：改为**按工作区隔离**的云端项目命名空间 `$DSH_HOME/handoff-projects/<projectKey>/{memory,journal.md}`，并保留跨任务的任务日志，实现"不同工作区隔离、同工作区连续"。

### 2.8 清理与保留策略

- **立即清理**：点「确认完成」/「丢弃」后，云端立即删除该 job 的**工作区副本、进出回传包、云端会话副本、任务记录**；本地回传包与解包缓存同步删除（`lib/index.js` `purgeJob` + `ack` 路由；`finishRetrieval`）。
- **兜底清扫**：终态任务（`DONE`/`ABORTED`/`FAILED`）超过 `retentionDays`（默认 `7` 天）由云端定时清扫——启动 30 秒后一次、此后每 12 小时一次（`lib/index.js` `sweepExpired`）。
- **上下文清理**：云端会话永不并入本地；子智能体只读有界摘要（见 1.2 第 4 条）。
- **依据**：`README.md`「清理策略」+ 上述代码位置。

## 三、已知失败模式与用户可见现象

| # | 失败模式 | 触发条件 | 用户可见现象 | 现状 |
|---|---|---|---|---|
| 1 | **云端回合中断 / 异常结束** | 云端 agent 执行中途报错、被 API 拒绝、或未调 `dsh_cloud_finish` 就结束（会话日志静默 ≥90s 且最后事件为 `turn/end`） | 本地卡片一直停在"云端仍在执行"；被收敛后显示"云端未正常完成，已保留中断前产出"，可点「回收进度」拉回中断前的变更 | 已解决：60s 扫描 + 查询时惰性收敛（`reconcileJob`），状态置 `STOPPED` 且产出可回收 |
| 2 | **任务卡死（已收敛）** | 云端 agent 跑完但没调 `dsh_cloud_finish`（2026-10-08 实测踩到） | 本地永远"云端仍在执行"，结果取不回来 | 已解决：同上 `reconcileJob` 自动打包回传 |
| 3 | **上下文过大被 API 拒绝** | 请求体超窗口（实测 16MB → 1,398,191 tokens） | 云端模型调用返回 `400`，回合异常结束（→ 落到第 1 条收敛） | 已规避：迁移只发简报；简报预算 300KB 默认，避免超窗 |
| 4 | **网络 / SSH 异常** | SSH 免密失效、主机不可达、端口漂移、超时 | 传输失败（`phase=传输失败`）或云端接单失败（`phase=云端接单失败`），本地任务 `FAILED` 并记录 `error`；轮询期间的网络抖动会被忽略、下轮重试 | 设计内：失败落库 + `operations.json` 记录；用「测试连通」先验证链路 |
| 5 | **云端会话活体冲突（SESSION_LIVE）** | 同一会话 id 在云端仍有活体实例（旧导入路径） | 接单失败；插件自动重启云端服务并重试一次（`receive` 失败 → `systemctl restart dsh-cloud` → 12s 后重试） | 已内置重试协议 |
| 6 | **真实发送报"缺少任务简报"（历史 bug）** | v0.3.5 及更早：`buildTaskBrief` 返回字段名与打包器读取不一致，真实发送即失败（干跑测试手工构造了 `{text}` 没暴露） | 点发送 → 报"缺少任务简报"，迁移失败 | 已在 `0.3.6` 修复，并新增"简报→打包"集成测试（`CHANGELOG.md`） |

> 现象说明：失败态（`FAILED`/`ABORTED`）都会写进 `~/.dsh/dsh-cloud-handoff/operations.json`（本地）与 job 记录，可用 `dsh_cloud_status` 或设置面板查看最近操作，便于事后追溯。

## 四、使用建议

### 4.1 适合交给云端的任务类型

- **分支 / 独立子任务**：可以从主任务中切出、目标清晰、可独立验收（例如"写一份文档 / 改一个模块 / 做一轮研究并产出文件"）。这是云接力定位——分支任务，不是主任务。
- **纯编写 / 测试 / 研究类**：云端在独立工作区里编写、运行测试、产出文件，不需要本机 GUI/浏览器交互。
- **长耗时、可无人值守**：合盖、关机、断网都不中断，适合"跑完再回来收结果"。
- **产出以文件形式可交付**：结果通过工作区 diff 回传，文件型产出（代码、文档、报告）最适合。

### 4.2 不适合交给云端的任务

- **需要本机浏览器 / GUI / 交互式确认**的任务（云端无头、无登录态）。
- **与主任务强耦合、需频繁往返确认**的活儿（往返成本高，还原容易出问题）。
- **依赖本机登录态 / 账号型模型 / 本机专用密钥**的任务（云端走 API Key、凭据不进包）。
- **工作区超大（>512MiB 或 >10 万文件）且无法瘦身**的项目。

### 4.3 任务描述怎么写

- **只写一两句话**即可：说清「目标 + 交付物 + 验收标准」。输入框无需写长篇——本地 agent 会据此整理成完整简报（`README.md` + `CHANGELOG 0.3.5`）。
- **不要指望把整段对话发上去**：插件发的是"你总结的子任务 + 主任务前情简报"，不是原始对话；细节靠简报里挑出的相关约束与工作区文件补足。
- **控制上下文体积**：简报预算 300KB、云端提示词再截 60,000 字符，越具体精炼，云端结果越好；无关内容别塞进任务说明。

### 4.4 回传结果验收方式

1. 云端结束后云朵亮绿点 → 点开卡片，**先点「查看报告」**用系统默认应用打开复盘报告，判断结论是否可信、方案是否可行（重点关注"给本地 agent 的实施建议"一节）。
2. 认可后点「交给当前会话落盘」→ 当前会话派**子智能体**读报告（`dsh_cloud_apply_result mode=report`）→ 结合本地完整代码库制定计划 → 实现并落盘；越界文件一律不应用。
3. 核对子智能体汇报：改动了哪些文件、与报告结论有何差异、遗留问题。
4. 确认无误点「确认完成·清理云端」，云端副本即被清除；忘记确认也有 7 天保留期兜底（见 2.8）。
5. 不认可就走「丢弃」，云端副本清除、任务作废。
